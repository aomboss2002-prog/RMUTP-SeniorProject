# สำรองฐานข้อมูลผ่านหน้าเว็บ

Admin เปิด **ตั้งค่า → สถานะระบบ → ตรวจสอบบริการเบื้องหลัง → สำรองฐานข้อมูล** แล้วกดยืนยัน ระบบสร้างไฟล์ `rmutp-database-วันเวลาUTC.sql.gz` และให้เบราว์เซอร์ดาวน์โหลดลงเครื่อง ไม่สร้างไฟล์สำรองไว้ในโฟลเดอร์เว็บหรือ Public Blob และไม่สำรองเองเมื่อหน้าเว็บรีเฟรช

## สิ่งที่อยู่ในไฟล์

- โครงสร้างและข้อมูลทุกตาราง InnoDB ในฐานข้อมูลที่เว็บเชื่อมต่อ รวมถึง `app_state`, การตั้งค่า, ประวัติ, AI และบัญชีผู้ใช้
- ข้อมูลส่วนบุคคล ค่าแฮชรหัสผ่าน และ Session อยู่ในไฟล์ด้วย: เก็บในพื้นที่เข้ารหัส จำกัดผู้เข้าถึง และห้ามอัปโหลดขึ้น Git หรือแชร์ลิงก์สาธารณะ
- **ไม่รวม** เนื้อหาไฟล์ PDF/รูปภาพใน `uploads` หรือ Private Blob, `.env`, Vercel Environment Variables และไฟล์โค้ด ต้องสำรองส่วนเหล่านี้แยกต่างหาก
- เป็นสำเนาฐานข้อมูลที่เว็บกำลังใช้: localhost และ Production อาจเป็นคนละฐานข้อมูล ตรวจ URL ก่อนสำรอง

## ขอบเขตและความปลอดภัย

- ใช้ Admin session + CSRF และต้อง POST พร้อมยืนยัน จำกัดการเริ่มงานหนึ่งครั้งต่อนาทีต่อ Session
- อ่านข้อมูลใน read-only / repeatable-read transaction โดยไม่แก้หรือลบตารางต้นฉบับ และอ่านข้อมูลทีละแถวเพื่อลดหน่วยความจำ
- ควรหลีกเลี่ยงการเปลี่ยน Schema / deploy migrations ระหว่างสำรอง; Snapshot ไม่ป้องกัน DDL ที่เกิดพร้อมกัน
- จำกัด SQL ก่อนบีบอัด 24 MiB, ไฟล์ gzip 2 MiB เพื่อไม่ชนขนาด response ของ PHP บน Vercel ตรวจเวลาระหว่างขั้นตอนที่ 20 วินาที (ไม่สามารถตัด SQL ที่กำลังรออยู่ได้ทันที)
- หากเกินขนาด/เวลา เกิดข้อผิดพลาด หรือพบ View, Trigger, Routine, Event, Spatial column หรือตารางที่ไม่ใช่ InnoDB จะไม่ส่งไฟล์สำรองบางส่วน ให้ใช้ backup ของผู้ให้บริการหรือ `mysqldump` แทน
- ไม่ใช่ระบบสำรองอัตโนมัติหรือสำรองระดับเซิร์ฟเวอร์: ไม่รวมบัญชี MySQL / GRANT และมีสิทธิ์อ่านตามบัญชีฐานข้อมูลของแอป
- SHA-256 ที่แสดงใช้เทียบไฟล์ gzip ที่ดาวน์โหลด แต่ไม่ใช่การเข้ารหัสไฟล์

## ตรวจไฟล์และกู้คืน

1. ตรวจว่าไฟล์อยู่ใน Downloads จริง เทียบ SHA-256 ด้วย `Get-FileHash -Algorithm SHA256 -LiteralPath 'พาธไฟล์.sql.gz'`
2. แตก gzip ด้วยโปรแกรมที่รองรับ จะได้ `.sql` ที่ลงท้ายด้วย `-- END RMUTP BACKUP`
3. สร้าง **ฐานข้อมูลใหม่ที่ว่าง** บน MySQL/MariaDB รุ่นที่เข้ากันได้ แล้วนำเข้า `.sql` ด้วยเครื่องมือฐานข้อมูล ไม่ใช้กับฐานข้อมูลเดิมที่มีข้อมูลอยู่แล้ว
4. ตรวจจำนวนตาราง ข้อมูล ภาษาไทย และเอกสารอ้างอิงก่อนสลับเว็บไปฐานข้อมูลที่กู้คืน ไม่มีปุ่มกู้คืนทับข้อมูลในหน้าเว็บนี้
5. เมื่อกู้คืนใช้งานจริง ควรยกเลิก Session / Reset Token เดิมตามนโยบายระบบ และกู้ไฟล์อัปโหลดที่สอดคล้องกันด้วย

## ทดสอบสำหรับผู้พัฒนา

```powershell
C:\xampp\php\php.exe tests\verify-database-backup.php
node tests\verify-health-refresh.mjs
```

ชุดทดสอบ PHP ปกติไม่ต่อฐานข้อมูล สำหรับทดสอบส่งออกและนำเข้าจริงต้องเปิด MariaDB ทดสอบแยกในโฟลเดอร์ชั่วคราวที่ขึ้นต้นด้วย `database-backup-` ตั้ง `BACKUP_TEST_PORT` เป็นพอร์ตที่ไม่ใช่ 3306 แล้วรันทดสอบอีกครั้ง สคริปต์ตรวจ `@@datadir` ก่อนสร้างฐานข้อมูลชื่อสุ่ม และลบเฉพาะสองฐานข้อมูลทดสอบที่มันสร้าง ไม่มีการอ่าน `.env` หรือต่อ Production
