# ลบโครงงานโดย Admin

หน้า **โครงงาน** มีปุ่มถังขยะ ต้องพิมพ์รหัสโครงงาน (เช่น `PRJ001`) ให้ตรงก่อนยืนยัน ควรสำรองฐานข้อมูลและไฟล์ก่อนลบ ไม่มีปุ่มกู้คืนบนเว็บ

- ลบโครงงานและเอกสารของโครงงาน รวมถึงผลพิจารณา ความคิดเห็นที่ผูกเอกสาร ประวัติความก้าวหน้า บันทึกติดตาม และผล AI
- ลบรายการ Runtime ที่ระบุ `project_id` หรือ `document_id` ของเป้าหมายอย่างชัดเจน ไม่เดาจากชื่อหรือบัญชีนักศึกษา จึงไม่ลบความคิดเห็นทั่วไป/ข้อความกลุ่มที่ไม่ได้ผูกโครงงาน
- คงบัญชีนักศึกษา อาจารย์ กลุ่ม สมาชิกกลุ่ม และสถานะการศึกษาไว้ ตัด `project_id` ของนักศึกษา/กลุ่มที่อ้างถึงโครงงานนั้น
- เก็บ Audit log ของการลบเพื่อให้ตรวจสอบผู้ดำเนินการย้อนหลังได้
- ลบข้อมูลฐานข้อมูลและปรับ Runtime ภายใน Transaction เดียว หากผิดพลาดก่อน Commit จะ Rollback
- หลัง Commit จึงลบไฟล์ PDF ใน Local uploads หรือ Private Vercel Blob โดยไม่ลบไฟล์ที่เอกสารอื่นยังอ้างอิง
- หากลบไฟล์ไม่สำเร็จ จะเก็บรายการค้างใน `app_state` แยกจาก Runtime และแสดงปุ่ม **ลองลบไฟล์ค้างอีกครั้ง** ในหน้าโครงงาน แม้เปิดหน้าใหม่ รายการก็ยังอยู่ ไม่ต้องลบโครงงานซ้ำ
- หากเปลี่ยน Storage driver, Blob store หรือ prefix ระหว่างงานค้าง ระบบจะหยุดลบไฟล์จนกว่าจะใช้ตำแหน่งเดิม เพื่อป้องกันลบผิดพื้นที่

Admin session และ CSRF จำเป็นสำหรับคำสั่งลบทั้งหมด ไม่มีการลบอัตโนมัติเมื่อเปิดหน้า ข้อมูลที่ลบจริงกู้คืนได้จากสำเนาฐานข้อมูลและไฟล์สำรองเท่านั้น

## ทดสอบ

```powershell
C:\xampp\php\php.exe tests\verify-project-delete.php
node tests\verify-project-delete-ui.mjs
```

Integration test ใช้ `PROJECT_DELETE_TEST_PORT` กับ MariaDB ทดสอบใน Temp directory ชื่อขึ้นต้น `project-delete-` เท่านั้น ไม่อ่าน `.env` และไม่ต่อฐานข้อมูลจริง ทดสอบด้วย Schema ของโปรเจกต์ รวมกรณี Rollback, ไม่ลบบัญชี, ไฟล์ใช้ร่วมกัน, ลบไฟล์ล้มเหลวและลองใหม่ โดยจำลองคำสั่งลบไฟล์ ไม่ส่งคำสั่งลบไปยัง Vercel
